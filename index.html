最難的設計

工作人員的餐廳座位流程

大團用餐時，工作人員要在 APP 上依車次把旅客分到各桌，到了現場還要帶位、確認餐點。這是整個專案最複雜的一段流程。

  • 以車次為單位分派同一車的旅客可以分到不同桌，素食旅客可以集中到素食桌。
  • 即時檢查座位用＋／－調整每桌人數，畫面即時顯示剩餘座位；超過上限會提醒，分錯可以取消重來。
  • 現場帶位與確認餐點可以依車次查看各桌名單，方便帶位；也可以依桌次查看特殊飲食狀況，方便確認餐點。
  • 資料隨時會變一般車次和自選行程車次都要分派，餐食或行程變更後也可能要重排，所以分派結果必須能隨時修改。

操作流程

大團 APP 的運作分成兩段：出發前，後台依序建立出團、匯入梯次與旅客、綁定車次與領隊；出發後，旅客在 APP 上報到、點餐並申請變更，由工作人員或領隊審核，結果再以推播通知。

梯次、旅客與自選名單都用 Excel 範本匯入。這是刻意的設計：客戶原本就用 Excel 整理資料，沿用同樣的作業習慣，導入時不用改變做法。

Case 03

蘭瑞診所 APP診所會員

專案｜Project

麗彤集團旗下抗老診所的會員 APP 與後台，提供線上預約、療程介紹、健康秘書與推播。

挑戰｜Challenge

預約和健康量測都要串接外部系統，但文件不完整；血壓量測功能又讓 APP 審查多次退件。

角色｜My Role

專案唯一 PM，負責企劃、規格與測試。同集團的電商網站與醫美門店 APP 也由我企劃。

成果｜Outcome

通過 Apple 審查並完成上架（目前已下架）。

01

串接「領健」預約系統

預約要串接診所使用的領健系統，但客戶只提供 Swagger 文件。

我的做法自己讀 API 文件，實際呼叫 API 驗證欄位和回傳資料，再逐欄寫進規格：哪個畫面用哪支 API、領健沒有資料時怎麼顯示。

02

串接量測儀器 SDK

健康秘書要顯示血壓與情緒壓力指數，資料來自量測儀器。

我的做法規劃量測流程與結果頁，把 SDK 回傳的各項指標對應到畫面，並定義數值區間和紅、橘、綠燈的呈現方式。

03

Apple 審查多次退件

Apple 把血壓量測視為醫療器材相關功能，審查多次退件。

我的做法撰寫 APP 操作說明，並向血壓計廠商取得證明文件，連同免責聲明一起補件，最後通過審查。

規格案例立即預約：欄位、資料來源與例外處理
欄位資料來源規則查無資料時
就診類型固定選項諮詢（預設）或美療。—
診間診所系統列出該診所的治療房間與手術房間。—
人員診所系統的排班諮詢列出醫師，美療列出美容師；預設帶入前一頁選的醫師。查無該醫師時改為「不指定」。
日期診所系統的預約資料列出所選人員有排班的日期，沒有排班的日期反灰；可預約兩個月內的日期。沒有指定人員時列出所有日期。
時段診所系統的班表醫師依診間設定的時間為單位，美容師依後台設定的療程時間為單位。沒有可預約時段時，提示改選其他日期。
送出預約—寫入前再確認一次所選時段是否已被預約。已被預約時提示重新選擇。

我怎麼做

  • 需求定義把一件物品拆成品名、類別、到期日、庫存數量、存放位置與備註，類別分食品、美妝、藥品，也能自訂代表色與排序。
  • 與 AI 協作實作和 Claude 一起寫出網頁前端與 Google Apps Script 後端，用 Google Sheets 存資料，不需架設伺服器。
  • 主動提醒綁定 Telegram，每週一上午 9:00 自動推播即將到期的品項。
  • 操作細節庫存歸零時詢問要保留還是刪除；搜尋找不到時可一鍵新增；寫入試算表前過濾以 = + - @ 開頭的內容，避免公式注入。
